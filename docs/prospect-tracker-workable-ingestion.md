# Prospect Tracker: limited Workable URL import

Date: October 14, 2026. Implements the user-authorized adapter from the [compatibility spike](prospect-tracker-workable-spike.md). Local implementation and validation are complete. Hosted deployment/acceptance status is recorded below; local checks alone do not establish hosted compatibility.

## Supported links and behavior

Accept `https://apply.workable.com/{account}/j/{shortcode}/`, with optional trailing slash and `/apply` variants. Account and shortcode are bounded ASCII tokens; case is preserved. Known `utm_*` tracking parameters and fragments are removed from the canonical URL; unknown query parameters remain recorded but are never forwarded upstream. Duplicate identity is provider + account + shortcode.

Accountless `/j/{shortcode}` links are intentionally unsupported. Open one in a browser and copy the resolved address containing the company account. Custom domains, legacy employer subdomains, board listings and search routes remain unsupported. No redirects are followed.

The existing `job-ingest` function constructs two public GET destinations on the exact host `apply.workable.com`:

1. `/api/v2/accounts/{account}/jobs/{shortcode}` for one posting.
2. `/api/v1/accounts/{account}?full=true` for employer metadata.

These are observed public careers-client interfaces, not a documented stable detail contract. No employer credentials, full-board downloads, runtime endpoint discovery or script execution are used. The adapter enforces exact returned shortcode, published/noninternal availability, valid account UUID and matching metadata subdomain/UUID. Wrong or missing account bindings in returned JSON fail closed. Optional metadata transport, malformed-JSON, access or size failures retain job facts with Company blank and a warning; cancellation/deadline still aborts everything.

Description, requirements and benefits are converted to complete plain-text sections with labels, using the existing inert parser. Company/title remain editable and required before saving. Public locations are retained; hidden locations are excluded and ambiguous list visibility is warned/omitted. If the locations list is absent, the primary location may be used unless explicitly hidden. An empty list does not trigger that fallback.

Explicit workplace values map to remote/hybrid/onsite. Conflicting remote flags leave arrangement blank. `remote: false` never establishes onsite. Only verified employment code `full` maps to Full-time; unknown codes remain blank with warnings. Salary extraction is deferred: pay prose remains in the description, and Compensation stays editable/blank. Supplied publication timestamps appear in warnings; Posted date stays blank because original-versus-republication semantics are unverified. Capture date uses the existing editable UTC default. No source channel, status, notes, assessments or connections are generated by ingestion.

## Boundaries and integration

The preview uses method `workable-public-job-detail` with the existing draft/provenance/warnings envelope. Existing browser validation, duplicate review, Cancel, explicit Save and database-trigger history are reused. Retrieval has no database access. There are no migrations, generated-type changes, new dependencies or secret changes.

Existing owner authentication, JWT verification and exact-origin CORS remain. Outbound work is at most two ATS requests, each bounded to 1 MiB of decoded bytes, within the existing 15-second shared deadline. The request remains bounded to 4 KiB and URLs to 2,048 characters. Access denials are distinguished from unavailable postings; throttling, redirects, invalid JSON and oversized job bodies fail with editable/manual-entry recovery. Metadata uses the same deadline and cannot follow arbitrary hints or leak bearer tokens.

Code lives in `tools/prospect-tracker/ingestion/workable-url.js` and `workable.js`, with recognition/dispatch/type variants in `posting-url.js`, `pipeline.js` and `preview.js`. Provider copy is in `ingestion-ui.js` and About. The entry import map versions `posting-url.js`; bootstrap/app/ingestion-UI revisions prevent cached provider modules from blocking the new feature. Tooling remains scoped to Prospect Tracker.

## Validation

Passed locally:

- 113 scoped Node tests, application typecheck/lint, function typecheck/lint and six Deno tests. New cases cover URL normalization attacks, short-link guidance, exact identities, unpublished/internal jobs, public/hidden locations, complete inert descriptions, missing/conflicting facts, provenance validation, duplicate aliases/distinct identities, error statuses, streamed/advertised size bounds, cancellation and the shared deadline.
- Synthetic SDK persistence tests: retrieval/Cancel wrote nothing; failed Save retained preview facts; retry created one normal prospect and one history event, with missing salary stored as null.
- Native public-fetch checks for Workable and Hugging Face: exactly two ATS requests each, verified company/title, hybrid/remote arrangement and complete description sections passed the browser preview decoder. No bodies were archived and no live records were saved.
- Local browser: full preview, edit/Cancel, required missing Company, short-link guidance, failed-save retention/retry, saved details/history/reload, duplicate detection for `/apply` and tracking aliases, and ordinary-Save blocking until duplicate review. The native draft-discard confirmation during Open existing stalled browser automation; completing that particular browser interaction and Save separately remain acceptance gaps. The shared behavior was not bypassed or modified.
